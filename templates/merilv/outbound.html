The confirm attributes sit on the BUTTON, not the form: datatable.js submits via `trigger.form`, which only exists on a form control. On a
it falls through to `trigger.click()`, and clicking a form submits nothing. A session with a finished delivery is refused by the view, and a picker may only delete one with no scans; neither is hidden here, because the view's message explains the refusal and a disabled button with no reason is worse than a clear rejection. No data-mv-confirm-type. It used to make the operator type the session's name — "MHPL 16 Sep 12:08" — before the button would arm, which on the screen they clear wrong uploads from is a transcription exercise, not a safety check. The confirm still names what is about to go, and the server refuses the dangerous cases outright whatever the dialog says; typing it out added nothing either of those does not already do. {% endcomment %} {% comment %} data-mv-async: posted where it stands and answered with a toast, the row removed on success.
