{% comment %} Matomo tracking, shared by every user-facing page. Lives here rather than only in base.html because several apps render full HTML documents of their own (AI Sales Agent, Shipment Notifications, the auth pages, the print/approval views) and so never inherit base.html — those pages were invisible to Matomo, which made the per-module breakdown under-count them. Include this immediately before in any template that does not extend base.html: {% include "_matomo.html" %} `matomo_module` and `MATOMO_ENABLED` come from core.context_processors.app_settings, so the include needs no context of its own — but the template must be rendered with a request (render(request, ...)), otherwise the context processors never run. The guard is MATOMO_ENABLED and not Django's `debug`: that variable is only set when DEBUG is on AND the request IP is in INTERNAL_IPS, and behind nginx every request comes from 127.0.0.1, so on a DEBUG deployment `not debug` silently blocked tracking for real visitors. Note it is the context processor's MATOMO_ENABLED, not settings.MATOMO_ENABLED: the setting is only the kill switch, and the processor also requires the request host to be a production one (settings.MATOMO_HOSTS). So a dev container is out of the analytics by default, without anyone having to configure it. {% endcomment %} {% if MATOMO_ENABLED %} {% endif %}
