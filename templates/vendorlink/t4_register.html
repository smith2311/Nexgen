That keeps server-side validation, the email OTP and the captcha exactly as they are — reimplementing a public write path that creates real vendor records, to gain a progress bar, would be a bad trade. Two consequences worth stating: * With JavaScript off, every fieldset is visible and the form still submits. The stepper is progressive enhancement, not a requirement. * Next does not validate server-side. Fields carry their native constraints so the browser catches the obvious, and the server remains the authority — a step that "passed" client-side can still come back with errors, which is why errors render inline against their own field rather than as a summary on a step the user has already left behind. {% endcomment %} {% block title %}Register as a vendor — Meril VendorLink{% endblock %} {% block extra_css %}{% include "vendorlink/_vl_head.html" %} {% endblock %} {% block content %}
