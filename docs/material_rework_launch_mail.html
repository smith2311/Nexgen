Material Rework is Live

One digital workflow to raise, approve, release, rework, receive and report material rework — with every quantity and every action attributable.

Where to find it: Sign In to nexgen.e-meril.in and open Material Rework from the left sidebar, or the Material Rework tile on your dashboard.

Dear Team,

We are pleased to announce the launch of the Material Rework module. It replaces the spreadsheet-and-email handling of rework requests with a single tracked workflow, so that at any point it is clear where a batch is, who it is waiting on, how much material has physically moved, and what has been reworked, lost or received back.

01
Raise
Upload a request on the standard Excel template, validated against master data.
02
Route & review

03
Rework & close
Release to production, rework, return, count back in, and close with a full record.

What the module does

✓ Excel upload with validation. Requests are raised on a downloadable template and checked against the master data before the batch is created — an unknown country, vertical or department is rejected at upload rather than discovered three stages later.
✓ Configurable approval flows. Who reviews a batch is master data, not fixed code. An admin sets rules per Requested By and per Type of Rework on the Routing Rules screen, and a batch takes the matching chain.
✓ A batch's route is fixed when it is raised. Changing a routing rule affects new requests only. Work already in motion can never be re-routed, stranded or have a stage skipped under it.
✓ Role-based queues. Each team sees only what is waiting on them — Order Management, PPIC, Production and Warehouse each have their own inbox, ordered by priority.
✓ The full physical rework cycle. Warehouse release to production, rework on the floor, production return, and warehouse receipt and count — each leg recording quantity, person and time.
✓ Partial acceptance and rework loss. Production accepts a quantity per line rather than all-or-nothing; the balance stays pending. Material lost during rework is recorded with a reason, so the shortfall is explained rather than unaccounted.
✓ Receipt mismatch flagging. If the quantity counted back into the warehouse does not reconcile, the line is flagged as a mismatch instead of quietly closing.
✓ Rework slot booking. Production books a slot window against the batch, so a request carries the dates the work is planned for.
✓ Priority and reference numbers. Every batch carries High / Medium / Low priority and a unique reference number to quote in any conversation about it.
✓ Email notifications with action links. Each stage notifies the responsible team's mailbox with a secure link into the batch, so a reviewer can act straight from the mail. The link binds to the first browser session that opens it and will not work from another, so a forwarded mail cannot be used to approve on someone else's behalf.
✓ Reports, exports and labels. A filterable report with Excel and CSV download, printable batch labels, and per-user activity so the record shows not just what happened to the material but who moved it.
✓ Live status on your own uploads. The person who raised a request can see where it is and what each reviewer said, without asking anyone.
✓ Rejections carry their reason. A rejected batch shows which stage rejected it and the reviewer's comments, so the requester knows what to correct before raising it again.

Role-wise access

Your role decides which queues and actions you see. Ask the module admin if you need a role changed.

Role What they do
Material Rework User Raise requests by Excel upload and track their own batches and reviewer comments.
Order Management Review the OM queue and approve or reject, with comments recorded against the batch.
PPIC Review the PPIC queue and approve or reject before the batch reaches its terminal stage.
Production Confirm accepted quantity per line, book the rework slot, carry out the rework and return it with reworked and lost quantities.
Warehouse Release material to production against the batch, then receive and count it back in, recording inward/outward numbers and any mismatch.
Admin Manage users and roles, all master data, routing rules and reports, with visibility of every queue.

The former HOD approval step has been retired — no flow routes to it. Existing HOD members remain visible on the user screen so their access can be reassigned.

What each request records

Stage Captured
Batch header Reference number, company, vertical, department, requested by, type of rework, location, priority, rework slot from/to, subject, raised by and raised at.
Per material line Material code, batch, serial number, manufacturing and expiry date, from/to country, from/to storage location, quantity, box number and remarks.
Review Reviewer name, e-mail, decision, comments and timestamp — recorded separately for Order Management, PPIC and Production.
Production review Accepted quantity, pending quantity and production remarks per line.
Warehouse release Quantity released to production, handover remarks, released by and released at.
Production return Reworked quantity, quantity lost in rework, rework loss reason, returned by and returned at.
Warehouse receipt Quantity received, inward and outward number, warehouse remarks, receipt mismatch flag, received by and received at.

The flow, end to end

Standard: Upload → Order Management → PPIC → Production review (accept quantity, book slot) → Warehouse release → Production rework → Production return → Warehouse receipt & count → Closed and reportable.

Production-raised: where Production is the requester there is nothing for Production to approve, so the batch goes straight into the warehouse leg carrying the slot the uploader committed to.

Gates and their order are configurable; the sequence above is the default. A requester with no rule configured takes the longest chain, not the shortest — an extra approval is an inconvenience, a skipped one is a material loss.

Please use the Material Rework module for all material rework activity from now on. Requests raised outside it will not be tracked, reportable or auditable.

Note on naming: this module was previously referred to as Material Disposition. That name is retired — Material Rework is the current and only active module.
